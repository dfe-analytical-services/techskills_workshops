What is Git?

Git is a piece of software designed for version control, and can be used for:

  • Tracking changes
  • Undoing changes
  • Maintaining parallel variants of code

Git works with repositories:

  • A repository (repo) is a folder containing all the version controlled files of a given project
  • It can have multiple sub-folders that can also be tracked

Git records all the version control information within a hidden folder called .git

And DevOps and GitHub…?

DevOps and GitHub provide a space to store and interact with a repository:

  • Store a central, shared back-up of your repository
  • View the files in the repository
  • View its history
  • Create and view different branches (variants) of the code
  • Create pull requests, review code and get feedback from collaborators
  • Perform automated QA and deployment of code (e.g. sending a dashboard live)

They also have management tools such as Issues logs (GitHub) or Kanban boards (DevOps)

And DevOps and GitHub…?

DevOps and GitHub are generally not a place to:

  • Run your code
  • Edit your code (although there is some basic text editing functionality you can use)

What’s the difference between Git, GitHub and Azure DevOps?

  • Git is the underlying software that you, GitHub and Azure DevOps use, providing the commands to record changes, create branches, merge branches, undo changes, etc.
  • GitHub provides a public space to store a shared copy of your repository, with features to plan, manage and share your work publicly
  • Azure DevOps provides a secure space to store a shared copy of your repository, with features to plan, manage and share your work internally within DfE

What are the key benefits of using Git?

  • Collaboration
    • Get support from team and wider community by easily sharing code (our team find it much easier to support you if we can just go and clone your repo…)
  • Straightforward code QA via reviews and automated checks
  • Helpful for continuity
  • Easy to undo changes
  • Try different methodologies in a properly controlled way

What does interacting with Git look like?

You can use Git from with RStudio, Visual Studio and GitHub Desktop using nice graphical user interfaces. At their heart though, all of these run the Git command line functions. The key ones that you’ll call on a lot (however you choose to interact with Git) are:

  • git clone <repository-url>
  • git add .
  • git commit -m "This is a message describing my latest changes"
  • git push
  • git pull
  • git checkout -b <branch-name>
  • git merge <branch-name>

These 7 commands are the main things you need to start tracking your projects using Git.

A closer look at Azure DevOps

  • A place to manage projects involving code development, e.g.
    • Reproducible analytical pipelines
    • RShiny dashboards
  • This includes:
    • Team task/Kanban boards
    • Remote repository storage and management – create branches, pull requests, change tracking, collaboration
    • Deployment pipelines (e.g. for deploying R-Shiny apps to rsconnect)

Azure DevOps has a lot of overlap with GitHub. The key benefit of DevOps over GitHub for analysts in the DfE is that it’s private.
